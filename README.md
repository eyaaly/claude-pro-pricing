## 钱花了，额度是怎么算的

Claude 的限制是双层的。会话限制每 5 小时重置一次；周限制叠加在会话限制之上，在每周的固定时间重置，这个时间由账号决定，跟你是哪天订阅的没关系。两个计时器彼此独立，新建聊天、退出登录、换浏览器，都不会让它们提前归零。

还有一个容易让人意外的机制：网页聊天和 Claude Code 共享同一个额度池。在终端里跑一次长时间重构，和在浏览器里进行一次长对话，消耗的是同一份额度。想看剩余用量，网页端打开 Settings > Usage，Claude Code 里输入 `/status`。

Anthropic 不公布消息条数，因为用量按 token 计算，消息长度、附件大小、是否调用工具都会影响消耗。可以确认的是，Pro 每个会话的用量至少是免费版的 5 倍。

烧额度的大头其实很集中：长对话（每一轮都会把之前的完整上下文重新发一遍，第 40 轮的消耗可能是第 1 轮的数倍）、大附件、网页搜索和 Research 这类工具、高 effort 档的扩展思考，以及反复重新生成的 Artifacts。对应的省额度习惯也简单：参考文档放进 Projects 而不是每次重复上传，相关的问题合并成一条消息发，换话题就开新对话。

上下文窗口方面，付费套餐标准是 200K tokens；Opus 5 和 Sonnet 5 在付费套餐中支持 1M tokens，不过在 Pro 上想给 Opus 用 1M 上下文，需要先启用超额用量功能。

## 什么情况下该升级，什么情况下不用

四个信号指向更高的套餐，而且都不靠感觉：

1. 不止一次在一周结束前用完每周限额。
2. 每月都在超额用量上实际花钱——把这笔钱加到 20 美元上，再和 100 美元的 Max 5x 比一比。
3. 单个任务没法在一个会话窗口内完成，工作总被重置周期打断。Claude Code 处理大型代码仓库时最容易撞上。
4. 需要多个人共用账号。这违反消费条款，而且大家挤的是同一份额度。

如果只是偶尔在某个高强度会话里触顶，问题多半出在用法上：缩短对话、用 Projects 缓存文档，比升级便宜得多。
